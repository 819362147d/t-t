# 细化桶分析报告（第六遍）：十分位 / 极端尾部 / 峰值带冻结验证

研究对象：cloud-trader 现行事件模型 + 7 标的，信号子集（prob ≥ 0.55 做多 / ≤ 0.45 做空），结果口径 win5 与 win10 双口径毛胜率。全程只读缓存 K 线，未下单、未用密钥、未触碰在跑的实盘与记录器进程。

> 本遍动因：用户指出前几遍的五分位桶太粗、指明性差。本遍把桶细化到**十分位**，并追加极端尾部细格与"峰值带冻结验证"，直接回答：胜率到底在指标的哪个窄区间里真的更高——如果有的话。
> 口径声明：本遍全部胜率为**毛胜率（不计摩擦）**，与前几遍一致；毛胜率高不等于能盈利。

## 口径与方法

- **数据**：复用 `events_all.csv.gz` 全部 17,717 个事件；ret5 与第四遍同法计算（锚点+4min 开盘 1m bar 收盘 / entry − 1），同法重算 ret10 对账最大偏差 = 0，ret5 缺失 0，21 个事件手工抽查全对（沿用第四遍校验，本遍重跑同一代码路径，校验再次通过）。
- **切分**：ts 60% 分位时间界，搜索段信号 1,533 个、验证段 1,040 个，与前五遍完全一致。所有边界只取搜索段，验证段原样套用（冻结）。
- **两类坐标**：状态量 `atr_norm`、`vol_z` 用原值；均值回归三指标 `mom_10m`、`rsi14_1m`、`rsi14_1h` 用**方向对齐坐标** a = −dir × 原值（dir：多头 +1 / 空头 −1）。于是对三指标：**D10 = 指标极端地处在"与信号相反"的位置**（多头刚跌过/超卖、空头刚涨过/超买，即均值回归对齐侧）；**D1 = 指标极端地与信号同向**（多头刚涨过、空头刚跌过，即动量延续侧）。高桶恒表示"状态站在均值回归一边"，下文按此读。
- **分桶边界**：按标的、在该标的搜索段信号子集上取坐标十分位（合并表 = 标的内十分位再合并，与第三遍"标的内排名再合并"同一处理，避免 atr_norm 等跨标的尺度差异污染合并桶）。注意这与第四遍五分位表（合并原始值边界）口径不同，两遍的桶不可直接对位——这点本身在结论里很重要（见结论 4）。
- **峰值带**：在搜索段枚举每个指标全部连续 1–3 个相邻十分位组成的带（每指标每口径 27 个），取搜索胜率最高者（并列取 n 大者）冻结，验证段原样评估并给 Jeffreys 95% CI。
- **多重比较总量**：十分位格 300 个（5 指标 × 10 桶 × 3 范围 × 2 段）、尾部统计 100 个、热力图格 400 个、峰值带搜索段扫描 810 个、冻结 30 个，合计约 **1,640 次**统计观察。在这个量级下，纯噪声也预期产生数十个"≥60%"的格子或带——本报告只认冻结后验证段的结果，且要求 CI 与基线可分、方向涨幅为正，才称得上"指明"。
- **参照基线**（无任何桶/门）：合并 win5 搜索 51.7% / 验证 52.5%，win10 搜索 53.8% / 验证 54.9%；BTC 验证 win10 58.1%（n=136）、win5 57.4%，XAU 验证 win10 73.0%（n=89）、win5 66.3%（第二、四遍同口径数字）。⚠ 标记 = 验证 n < 50，该格只作记录不作解读。

## 一、结论先行

1. **没有任何一个窄带通过"指明"检验。** 合并集 10 个冻结峰值带（5 指标 × 2 口径）没有一个能与合并基线（win10 54.9% / win5 52.5%）区分开：9 个的 CI 包含基线，剩下的 atr_norm win10 带 CI [26.7%, 52.9%] 整体位于基线之下（显著更差）；且其中 4 个的点估计直接塌陷到基线之下（atr_norm win10 带 57.6% → **39.2%**；vol_z 两个带 59.1%/58.5% → **47.5%**；mom_10m win5 带 56.7% → 49.3%）。把桶切细没有找到峰，只找到了更多噪声。
2. **两个"近失"也都不成立**：① mom_10m 对齐坐标 win10 的 D5 单桶带搜索 58.9% → 验证 **62.3%**（n=122），方向是对的，但 CI [53.5%, 70.5%]仍包含基线 54.9%——以现有样本量无法与基线区分；且其相邻桶并不配合（D3 验证只有 45.4%），是孤峰不是台地。② rsi14_1h 对齐 D1 带 win10 搜索 61.6% → 验证 **61.4%**（n=83），胜率数字复现了，但该带验证段**平均方向涨幅为 −0.036%**——赢的次数多、每次赢得小，输得少但大，期望为负。胜率复现而涨幅为负，这个"峰"是空心。
3. **细桶本身会塌：桶的人群在验证段大规模漂移。** 冻结边界下，验证段 atr_norm 十分位的人数是 D1=315、D3=**17**、D5=26、D10=316——中间桶几乎空了，事件全堆到两端（各标的波动状态在两段间整体平移）。rsi14_1h 对齐坐标同样：D3 一个桶吞了 322/1040，D10 只剩 14。逐标的更极端：XAU 的 rsi14_1h 验证段 D6/D8/D9/D10 **全空**、53/89 个事件挤在 D3；BTC 的 atr_norm D3 为 0。也就是说，即便某个窄带在搜索段是真的，冻结阈值到了新数据上也圈不到同一群事件——这正是第五遍 USOIL 对齐门 n=0 现象在桶口径下的系统性重演。
4. **第四遍的 atr_norm"Q2 驼峰"在本遍换一种合理分桶方式后不复现**：本遍 atr_norm 冻结带恰好落在 D2（搜索 57.6%），验证只剩 39.2%（n=51）。两遍口径不同（第四遍合并原始值边界 vs 本遍逐标的十分位），不能直接判谁对谁错；但"换一种分桶、峰就搬家或消失"这件事本身，就是"指明性差"的最直接证据——峰是分桶方式的产物，不是数据的结构。
5. **极端尾部不单调**：没有任何指标出现"越极端越好且两段同向"。搜索段最像样的尾部（vol_z 高尾 win10 从 10% 尾的 59.1% 升到 1% 尾的 69.6%）在验证段全面塌陷（5% 尾 50.0% 且平均方向涨幅 −0.194%，10% 尾 47.5% / −0.118%）；rsi14_1h 高尾在验证段直接样本枯竭（n=1~14）。尾部越细，人数越少、漂移越大，是过拟合最严重的地方。
6. **atr_norm × vol_z 的 10×10 热力图没有结构**：搜索段格值域 21%–85%（每格 n 仅 8–35，标准误 ±9–17 个百分点，与纯噪声完全一致），无任何行/列/对角脊线；验证段因 atr 桶塌陷，D2–D8 行合计每行只有 17–63 个事件、多数格 n ≤ 3，0% 与 100% 满格皆是 n=1–3 的产物。唯一有足够人数的 D1/D9/D10 行内，win10 沿 vol_z 十分位锯齿跳动，无单调或驼峰形态。

**一句话**：把桶从 5 个切到 10 个、再切到 1% 尾部，胜率曲面没有变出山峰，只是把噪声切得更碎；唯一被细化出来的真信息是负面的——冻结桶在新数据上连人群都保不住。指明性差不是桶不够细，是指标与方向之间本来就没有可指明的东西（与第三遍 ρ≈0.04 的量级一致）。

## 九、局限与底线

- **有效样本量**：相邻事件结算窗重叠（win10 尤甚）、同标的特征高度自相关，所有 CI/z 只作量级参考，真实不确定性比名义值更大——这只会让上面的否定结论更保守，不会翻案。
- **分布漂移是本遍的二号主角**：8.8 天样本横跨不同波动状态，以搜索段分布定义的细桶在验证段人群塌陷（多处整桶为空、尾部人数数倍膨胀）。任何"窄区间"类规则——桶、带、硬阈值门——都共享这个脆弱性（与第五遍 USOIL 门 n=0 同源）。要让窄带可用，前提是先有能跨状态稳定的坐标（如按滚动窗口实时重排的相对分位），那是另一个设计，不在本遍范围。
- **多重比较**：本遍约 1,640 次统计观察叠加前五遍的数千次，mom_10m D5 这类近失的先验可信度应进一步下调。
- **底线**：六遍研究至此在"分桶/过滤"方向上形成闭环——五分位、十分位、1% 尾部、单指标带、双指标组合、方向对齐门，全部口径下都没有找到样本外成立的窄区间。细化分桶回答了用户的问题：**不是桶太粗，是曲面本来就没有峰。** 若还要在这个方向上推进，剩下的只有记录器正在积累的前向数据对 mom_10m D5、rsi14_1h D1 两个近失假设做事前复验（注意后者还需先解释涨幅为负的问题），或回到改模型/换信息源的老结论。

数据集与结果：`runtime/event_optim/events_all.csv.gz`（未改动）、`runtime/event_optim/analysis_buckets_results.json`（含全部十分位/尾部/热力图/峰值带明细与逐标的边界），代码 `event_optim/analyze_buckets.py`，可复现。本遍共计算十分位格 300 个、尾部统计 100 个、热力图格 400 个、峰值带扫描 810 个并冻结评估 30 个。
